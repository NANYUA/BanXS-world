# 翻页落位实验室（PageTurnLab）

一个**只有一屏**的 iOS 应用，用来回答一个问题：

> 滑动翻页松手那一下，到底是「毫不停顿继续滑到位置」，还是先顿一下再翻？

它不猜，直接量：**松手 → 首个屏幕帧**、**落位期间最大帧间隔**、**动画时长**、**落地后首帧**、**掉帧数**。
所有可疑原因都做成了开关，可以一次只改一个面，对比读数。

---

## 1. 跑起来

```bash
brew install xcodegen
xcodegen generate
open PageTurnLab.xcodeproj
```

选真机（**不要用模拟器**：模拟器帧率与真实调度都不是一回事），Run。

> 需要真机 120Hz 屏才看得出差别；60Hz 设备上「正常帧间隔」是 16.7ms，读数依然有效，只是分辨率粗。
> `CADisableMinimumFrameDurationOnPhone = YES` 已开，否则 iPhone 会被钉在 60Hz。

---

## 2. 怎么测（最短路径）

1. **先看现状**：预设选「现状」，慢拖约 30% 屏宽后松手，连做 5 次。
   - 左上角「松手 → 首帧」若明显大于 8.3ms（比如 20–40ms）⇒ 松手那一帧被重算拖住了。
   - 「落位期间最大间隔」若出现 30ms+ 的尖峰 ⇒ 动画中途掉帧。
2. **按「自动 A/B」**：九组预设各跑 8 次、取中位数，几十秒出表。
3. 看哪一组把「首帧」拉回 ~8ms、把「最大间隔」压到 ~9ms —— 那就是根因所在。

「自动 A/B」用的是程序化提交（没有手指），所以它验证的是**提交与落位这一段**；
手指本身的贡献要回到手动拖拽去看。

---

## 3. 开关 ↔ 假设对照

| 开关 | 对应假设 |
|---|---|
| **松手时重算父级** | ① 松手同帧里 `ReaderView.body` 全量重算（HUD / 章节列表），动画首帧被推迟 |
| **换页推到下一帧再做** | ①+ 把索引变化与三格重建挪到动画之后一帧，先让动画起步 |
| **落位动画 = 速度反解** | ②③ 固定 `.easeOut(0.28)` 与剩余距离、手指速度脱钩：拖 90% 也只走 0.28s，`easeOut` 起手速度却是平均值的 1.72 倍 ⇒ 观感「先冲一下再慢慢挪」 |
| **落位动画 = 弹簧** | ② 让落位继承手指初速（`initialVelocity = v/1000`），位移与速度连续 |
| **预渲染 = 下一 runloop** | ④ 落地同帧同步渲染三张整页位图（真跑三次 CoreText 排版） |
| **跟手位移不夹 ±一页宽** | ⑤ 夹紧后后半段不跟手；且夹满一页时松手 `offset += W` 恰好变 0，落位动画被整个跳过 |
| **发起 = turnRequest** | ⑥ 点击翻页走 `turnRequest → onChange`（流畅），手势松手直接调 `commit`（不流畅）——同一段动画两个发起时机 |

预设列表里还有「全改」：下一帧提交 + 速度反解 + 预渲染延后 + 不重算父级。

---

## 4. 读数怎么判

| 读数 | 正常 | 异常含义 |
|---|---|---|
| 松手 → 首帧 | ≈ 一帧（120Hz 下 8.3ms） | 20ms+ ⇒ 松手那一帧主线程被占住（假设 ①） |
| 落位期间最大间隔 | ≈ 9ms | 30ms+ ⇒ 动画中途掉帧（假设 ④ 或父级重算） |
| 动画时长 | 与剩余距离/速度相关 | 固定 0.28s 而剩余只剩 10% ⇒ 尾巴拖沓（假设 ②③） |
| 落地后首帧 | ≈ 一帧 | 30ms+ ⇒ 落地那一帧在做别的事（假设 ④） |
| 掉帧 | 0 | 越多越糟 |

## 5. 结构

| 文件 | 作用 |
|---|---|
| `Sources/PageTurnLabApp.swift` | 入口，只有一屏 |
| `Sources/LabView.swift` | 页面、手势、提交、落位、面板、自动 A/B |
| `Sources/LabModel.swift` | 开关、九组预设、正文生成、工作量模拟 |
| `Sources/LabMeter.swift` | `CADisplayLink` 量帧，不参与布局 |
| `Sources/LabPageText.swift` | 一页正文（`UILabel` / TextKit）与统一排版属性 |

判据与真实阅读器一致：越屏中线就翻，否则看甩动速度（>500 pt/s 且位移 >8% 屏宽，方向须一致）。
